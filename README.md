# 安卓鼠标拓展

安卓鼠标拓展是一款以 Kotlin 编写的原生 Android 应用，可将快捷操作配置到屏幕四角。应用通过无障碍服务创建透明鼠标区域；每个角落可以独立设置一个悬停动作，以及多项由不同鼠标按键触发的动作。界面采用 Google Material 3 Expressive（MD3E）设计语言，并适配手机、平板和可调整大小的窗口。

## 功能

- 分别配置左上、右上、左下和右下角。
- 悬停与按键动作分别配置。每个角落最多设置一个悬停动作，以及最多五项按键动作；左键、右键、中键、后退侧键和前进侧键各自对应一个动作。
- 同一鼠标按键可在不同角落设置不同动作；同一角落内不能重复添加同一个按键。悬停动作与按键动作互不替代，可以同时启用。
- 从 v1.3.0 升级时，原有角落动作和触发方式会自动迁移为对应的悬停动作或按键动作。
- 鼠标悬停按可调停留时间触发；按键动作在指针位于角落时按下对应按键立即触发，松开不会重复执行。按键动作不受悬停停留时间影响。
- 为各角落选择关闭、返回、桌面、多任务、通知栏、快捷设置、锁屏、截图、分屏、打开应用托盘、打开指定应用或以小窗模式打开指定应用。系统操作的可用性取决于 Android 版本、设备和系统当前提供的能力。
- 在主界面统一选择最多六个托盘应用，并将“打开应用托盘”配置到角落。点按图标会打开应用；按住图标并拖出托盘会请求以自由窗口模式启动；点按托盘外区域可收起托盘，该次点击不会传递给下层应用。
- 托盘应用图标沿触发角扇形排列，不显示应用名称，也不使用额外的圆角矩形容器；可在“设置托盘应用”中选择圆形、圆角矩形或矩形图标。
- 可选在托盘展开时模糊其下方的当前界面，托盘收起后立即清除模糊；当系统关闭跨窗口模糊时，会以半透明遮罩保持托盘内容清晰。
- 托盘展开和收起带有轻微缩放与淡入淡出，应用图标依次出现；按住图标时提供按压反馈，拖出托盘后启动小窗。
- 可选接入 Shizuku，以 shell 身份明确请求系统用自由窗口模式启动目标应用，并在启动后调整任务边界。未启用 Shizuku 时仍使用 Android 标准窗口边界请求。
- “打开某应用”和“以小窗模式打开某应用”分别为每项动作保存目标应用；应用选择器支持按名称或包名搜索已安装的启动器应用。
- 使用停留时间滑块调整悬停触发延迟，范围为 0 至 1,000 毫秒，步进 50 毫秒，默认值为 300 毫秒。选择“立即”时不等待延迟。
- 默认启用左上角多任务悬停动作；其余角落默认关闭。
- 悬停动作每次进入角落最多触发一次；鼠标离开后重新进入，才会再次触发。按键动作每次匹配的按下事件触发一次。
- 仅响应鼠标输入，不响应触屏和触控笔输入。鼠标侧键的实际支持情况取决于设备是否通过 Android 鼠标按键事件上报。
- 屏幕方向或配置变化后，服务会重新定位角落区域。
- 设置页根据应用可用窗口宽度调整排版：小于 840 dp 时使用单列，达到或超过 840 dp 时切换为左右分栏，四个角落卡片以 2 × 2 网格展示。分屏或调整窗口大小时，页面会自动重新排版。
- 动作选择器会根据当前窗口限制尺寸；选项较多时可滚动查看。
- 设置页采用 Material 3 Expressive（MD3E）视觉风格，包括动态色彩、明暗主题、分组容器和清晰的文字层级。Android 12 及以上版本会使用系统壁纸色彩。
- 启动器图标采用自适应图标格式；Android 13 及以上版本支持系统主题图标所需的单色图层。

## 系统要求

- 最低支持 Android 8.0（API 26）。
- 锁屏和截图操作要求 Android 9（API 28）或更高版本。
- 分屏操作要求 Android 11（API 30）或更高版本，并且系统需向无障碍服务提供该操作。

## 安装与启用

1. 从 [GitHub Releases](https://github.com/ibka512/hot-corners-android/releases) 下载最新公开版 APK。当前公开版本为 [v1.4.1](https://github.com/ibka512/hot-corners-android/releases/tag/v1.4.1)，也可[直接下载 APK](https://github.com/ibka512/hot-corners-android/releases/download/v1.4.1/app-debug.apk)。
2. 安装并打开应用。
3. 在设置页点按“管理无障碍服务”，进入系统无障碍设置。
4. 在“已安装的应用”或系统对应列表中找到 **安卓鼠标拓展**，然后开启服务。
5. 返回应用，确认“触发角总开关”处于开启状态。
6. 在“托盘应用”中选择常用应用（最多六个）。点按四个角落卡片，在角落详情中设置悬停动作，并按需添加多个不同的鼠标按键动作；需要托盘时，将动作设为“打开应用托盘”。
7. 连接鼠标。悬停动作需要将指针移至该角并停留到设定时间；按键动作需要将指针放到该角并按下已配置的鼠标键。
8. 如需改善小窗启动兼容性，安装并启动 [Shizuku](https://shizuku.rikka.app/download/)，然后在本应用的“小窗启动增强”卡片中点按“授予 Shizuku 权限”并确认系统授权。Android 11 及以上可按 Shizuku 指引通过无线调试启动；也可连接电脑，通过 USB 调试启动。设备重启后，非 root 模式的 Shizuku 通常需要重新启动。

启用并授权 Shizuku 后，小窗启动会先请求 Android 自由窗口模式，再调整任务边界，以兼容会忽略普通应用窗口请求的系统。未启用 Shizuku 时，应用仍会尝试 Android 标准窗口请求。目标应用和系统都需要支持多窗口；HyperOS 等厂商系统可能会改写最终窗口尺寸或位置。

已在 Android 16、HyperOS 3 设备上，通过角落应用托盘将有道词典启动为自由窗口模式。此验证确认应用进入自由窗口，并不代表所有设备都会采用相同的窗口尺寸或位置。

关闭应用内的总开关会暂停全部角落操作；也可以在系统无障碍设置中关闭本服务。

## 无障碍权限与交互说明

本应用需要用户在 Android 系统设置中手动启用无障碍服务，才能在其他应用上接收鼠标悬停和鼠标按键事件并执行系统操作。Shizuku 为可选组件；仅在用户启用并授权后，小窗启动会通过其 shell 进程请求自由窗口模式。应用不会读取当前应用的无障碍窗口树，也不请求手势控制或触摸探索权限。角落配置保存在应用私有的本地 `SharedPreferences` 中。

已启用的角落会创建一个透明的 24 dp 区域，以接收鼠标输入。因此，触摸屏在该区域内的点按可能由透明窗口接收，但不会执行角落动作。按键动作只在该角落收到已配置鼠标按键的按下事件时执行；一个角落中的每个按键只对应一个动作。鼠标侧键可能被厂商映射为键盘事件，未必能作为鼠标按键捕获。未配置动作的角落不会创建透明窗口。

应用托盘展开时会覆盖全屏并暂时接收鼠标输入。点按托盘外区域会收起托盘，但该次点击不会穿透到当前应用；若要继续操作当前应用，请先收起托盘。

## 构建

项目使用 Android Gradle Plugin 9.4.0、Gradle Wrapper 9.6.0、Android SDK Platform 35 和 Build Tools 36.0.0。Kotlin 由 Android Gradle Plugin 提供；小窗增强接入 Shizuku API 13.1.5 和官方 Provider。为兼容部分小米／联发科系统上的 Shizuku UserService 初始化问题，当前实现使用该版本的命令进程桥；升级 Shizuku API 后应重新验证授权和自由窗口启动。

使用 Android Studio 打开项目，或在已配置 JDK 与 Android SDK 的环境中运行：

```sh
./gradlew :app:assembleDebug
```

构建完成后，APK 位于：

```text
app/build/outputs/apk/debug/app-debug.apk
```

安装到已连接的设备：

```sh
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

如需在命令行配置本机工具路径，可使用以下示例并替换为实际安装位置：

```sh
export JAVA_HOME="/path/to/Android Studio.app/Contents/jbr/Contents/Home"
export ANDROID_HOME="/path/to/Android/SDK"
export PATH="$JAVA_HOME/bin:$ANDROID_HOME/platform-tools:$PATH"
./gradlew :app:assembleDebug
```
